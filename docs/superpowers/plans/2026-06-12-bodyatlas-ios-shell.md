# BodyAtlas iOS Shell Implementation Plan (Phase 2c)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A thin Capacitor iOS shell per the spec: the WebView loads the live app at `https://bodyatlas.okdtsk.dev` (remote-URL mode — zero UI duplication, web deploys update the app instantly), plus ONE native capability: a custom `HealthSync` Swift plugin that reads Apple Health sleep and body-mass/body-fat samples and lets the web app import them.

**Architecture decisions (locked):**
- **Remote-URL mode** (`server.url` in capacitor.config.ts): the shell renders the production site, so the existing same-origin cookie session works natively — no CORS/cookie surgery, no bundled-asset staleness. Capacitor injects its JS bridge into the remote page, so the web app can feature-detect `window.Capacitor` and call the plugin. (Trade-off: the app needs network — which BodyAtlas does anyway, online-only by design. App Store review frowns on pure wrappers; this ships personal/TestFlight only.)
- **Custom minimal Swift plugin** over a community HealthKit dep: exactly two methods, no third-party native code.
- **Sync scope v1: sleep + weight/body-fat only.** HealthKit workouts don't carry sets/reps so they can't map onto BodyAtlas's strength model — deferred, noted in the spec's phase 2 ledger.
- **Direction: Apple Health → BodyAtlas** (import). Dedupe is client-side and day-keyed (device tz, consistent with the app's day handling): a Health-derived record is skipped when BodyAtlas already has a record on that local day (sleep keyed by wokeAt-day, measurements by measuredAt-day).
- **Sleep mapping:** HK `sleepAnalysis` category samples are fragmented; the plugin returns raw samples and the WEB side merges per night — group samples whose gaps are <2h, bedAt = earliest start, wokeAt = latest end, drop nights >24h, quality null.
- **SPM, not CocoaPods** (`npx cap add ios` with Capacitor's SPM integration; pod is not installed on this machine).
- The `ios/` directory is committed (standard Capacitor practice) except user-specific Xcode state.

### Task 1: Capacitor scaffold (remote-URL shell)

- [ ] Root: `npm install -D @capacitor/cli && npm install @capacitor/core @capacitor/ios` (root workspace — the iOS project is repo-level, not under app/).
- [ ] `capacitor.config.ts` at repo root:

```ts
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.okdtsk.bodyatlas',
  appName: 'BodyAtlas',
  webDir: 'app/dist/client', // required field; unused in remote mode but must exist for cap sync
  server: {
    url: 'https://bodyatlas.okdtsk.dev',
    allowNavigation: ['bodyatlas.okdtsk.dev', 'accounts.google.com', '*.google.com'],
  },
  ios: { contentInset: 'automatic' },
};

export default config;
```

Flag it; don't build it yet.)

### Task 2: HealthSync Swift plugin

- [ ] `ios/App/App/HealthSyncPlugin.swift` — CAPPlugin with two methods:
  - `requestAuthorization(call)`: HKHealthStore.requestAuthorization for read types `sleepAnalysis` (HKCategoryType), `bodyMass`, `bodyFatPercentage` (HKQuantityType) → resolve `{ granted: true }` (HealthKit doesn't reveal per-type grant status for reads; resolve once the prompt completes, reject on error).
  - `querySamples(call)` with `{ days: number (1-90, default 30) }` → three HKSampleQuery batches → resolve:

```json
{
  "sleep": [{ "start": "ISO", "end": "ISO", "value": "asleep|inBed" }],
  "weight": [{ "date": "ISO", "kg": 72.4 }],
  "bodyFat": [{ "date": "ISO", "pct": 18.5 }]
}
```

  Sleep: include only asleep-ish category values (`.asleepUnspecified/.asleepCore/.asleepDeep/.asleepREM` mapped to "asleep"; `.inBed` mapped to "inBed" — the web merge uses only "asleep" but receiving both aids debugging). ISO via ISO8601DateFormatter (UTC, with timezone). kg via `HKUnit.gramUnit(with: .kilo)`; pct via `HKUnit.percent()` × 100.
  - Register per current Capacitor plugin registration for the installed major (check the generated project: Capacitor 6+ uses `CAPBridgedPlugin` protocol with `pluginMethods` list — mirror whatever pattern the generated `ios/App` expects; consult node_modules/@capacitor/ios docs if unsure; report the registration mechanism used).
- [ ] `App.entitlements` with `com.apple.developer.healthkit` true, wired into the target build settings (CODE_SIGN_ENTITLEMENTS); Info.plist `NSHealthShareUsageDescription` ("BodyAtlas imports your sleep and body measurements from Apple Health." / keep EN — system shows it) and `NSHealthUpdateUsageDescription` omitted (no writes).
